//…): .FirstSection there is the section ("kubernetes"), not the version, so the `in $versionPath .linkVersion` substring check never matched and the banner just stopped appearing inside section subtrees. version-root.html already has to solve that same "where's the version" problem correctly for the sidebar and navbar; this reuses that answer instead of re-deriving a second, independently-broken one. When a version entry sets `bannerID`, look up a per-language translation via i18n and fall back to the literal `banner` string when no translation exists for the current language (e.g. English, which has no i18n table). The whole version entry is passed to i18n as the template context, so a translation string can interpolate its fields — e.g. a single shared key `"… the {{ .version }} version of {{ .productName }} …"` serves every older version instead of one hardcoded string per version. ── PER-SECTION OVERRIDE ──────────────────────────────────────────────── A version entry may also carry section-scoped banners, for a product whose sections sit at different maturities WITHIN one version: [[params.versions]] linkVersion = "latest" sections = ["kubernetes", "standalone"] banner = "This is the latest version…" bannerID = "version_banner_latest" [params.versions.sectionBanners.standalone] banner = "PREVIEW ONLY …" bannerID = "version_banner_preview" A page in a section that declares one gets it INSTEAD OF the entry-level banner, not stacked with it: "under development" next to "this is the latest version" reads as a contradiction, and the maturity notice is the one that matters. A section with no override falls back to the entry-level banner, and an entry with no `sectionBanners` behaves exactly as before — so this is a no-op for every consumer that does not set it. WHY THE OVERRIDE LIVES ON THE VERSION ENTRY, and not under `[params.sections.]`. Two reasons. 1. It is the right axis. Section maturity is a property of (section, version), not of the section: agentgateway's `standalone` is in preview at `latest` and will be GA at the next numbered version. A section-level banner cannot say that, and would keep claiming "under development" on the GA'd tree. 2. One place to look. Putting it on the section splits banner config across `params.versions[].banner` and `params.sections..banner` — two unrelated tables with an implicit precedence between them. That is the shape utils/resolve-section-versions.html documents removing in 0.2.2 ("a second, hand-maintained representation of the same fact. Nothing kept the two in step"), which was the shared cause of the flexsearch empty-set bug, the dropped-version-segment bug, and version-noindex being wholly inert on agentgateway.dev. WHAT NOT TO DO INSTEAD: do not split one version into two entries to get two banners. It builds clean and then misroutes, because the enterprise branch of version-root.html matches against the UNFILTERED site.Params.versions, so both sections receive whichever duplicate `linkVersion` is listed first. Measured on the docs hub: that put a standalone preview banner on 327 Kubernetes pages. One entry per version is a documented invariant, not an incidental one. DYNAMIC KEY LOOKUP USES `index` WITH A LOWERCASED SEGMENT. Hugo lowercases config param keys on load, so a TOML key written `sectionBanners` is stored lowercase; dot access (`.sectionBanners`) resolves case-insensitively through maps.Params, but `index` does a plain map lookup and is case-SENSITIVE. Hence `index … (lower …)`. */ -}} {{- $root := partial "utils/version-root.html" . -}} {{- $bannerText := "" -}} {{- $bannerID := "" -}} {{- $entry := $root.versionEntry -}} {{- /* 1. Section override on the SAME entry. utils/section-segment.html is the module's own "which registered section is this page in" answer — reuse it rather than re-deriving a second one off RelPermalink, which is the exact mistake this file's header calls out for version detection. It is a return-partial returning a DICT (segment, index): assign it, then read .segment. Never `with` a return-partial. */ -}} {{- if $entry -}} {{- $seg := partial "utils/section-segment.html" . -}} {{- if $seg.segment -}} {{- $overrides := $entry.sectionBanners -}} {{- if $overrides -}} {{- $o := index $overrides (lower $seg.segment) -}} {{- if $o -}} {{- /* Only a non-empty `banner` triggers the override.
