{{- /* Non-latest-version noindex — surgical (duplicates only). For versioned docs, an OLD version's copy of a page that STILL EXISTS in the current version is near-duplicate content competing for the same query, which splits ranking signal and often surfaces the old version. This marks those duplicates `noindex, follow` (follow so link equity still flows to the current version). Crucially, a page that exists ONLY in an old version — a feature that was removed in the current release — has NO current-version equivalent and is LEFT INDEXABLE, so it stays findable in search. That's the difference from a blanket per-version noindex: we suppress duplicates, not history. OPT-IN AND FAIL-SAFE. Activates only when the current version can be identified, by either of two signals (see the detection block below): an explicit `latest = true` flag, or a `linkVersion = "latest"` segment. [[params.versions]] version = "2.3.x" linkVersion = "latest" # auto-detected; no flag needed # latest = true # only needed when linkVersion isn't "latest" Detection is deliberately conservative rather than inferred from, say, a "(latest)"/"(current)" dropdown label — those are not uniform across repos (the docs hub even carries a stale "(latest)" label on an OLD entry), and guessing wrong would deindex live docs. A repo whose current version is a bare number and not served at /latest/ (e.g. docs hub) must use the explicit flag. Matching neither signal emits nothing — worst case is the pre-existing everything-indexable behavior. WHY noindex AND NOT canonical: Hextra's head.html has already emitted a self-referential `` before head-end.html runs, and the theme does not shadow head.html. Emitting a second, conflicting canonical makes search engines ignore BOTH; a second robots tag, by contrast, resolves deterministically to the most restrictive (noindex). So on a duplicate this emits an ADDITIONAL `` alongside Hextra's `index, follow`, and noindex wins. (A consumer wanting a single clean canonical-to-current tag can instead set `.Params.canonical` via a config cascade on its old version paths and leave `latest` unset here.) WHERE THE VERSION COMES FROM. `utils/version-root.html`, the one resolver the sidebar, navbar, docs-tabs band, version banner and link shortcodes also use. This partial used to scan the URL and build the lookup path itself, and being the only copy nobody tested, it was broken in two of the three consumer shapes: 1. On the docs hub it built the lookup path from the full RelPermalink, so it kept the // segment — but hub GetPage paths are relative to contentDir (content//), so `site.GetPage "/gloo-mesh-enterprise/latest/getting_started"` was ALWAYS nil and no duplicate was ever marked noindex. Measured: gme 2.10.x–2.12.x `getting_started` all served `index, follow`. `version-root.lookupPath` is exactly the contentDir-relative path this needs; sidebar.html and navbar.html strip the prefix for the same reason. 2. On a sections-only site (agentgateway.dev, whose versions live under params.sections..versions with no top-level list) the `with site.Params.versions` gate made the whole partial inert — no robots meta at all, while kgateway.dev got both tags correctly. `utils/resolve-section-versions.html` is the canonical answer to "which versions apply here" and handles both config shapes. Resolving the section's OWN version list also makes "latest" mean the latest of THIS section, which matters once two sections ship different version sets (agentgateway's kubernetes has more versions than standalone). Called once per page from head-end.html. */ -}} {{- $root := partial "utils/version-root.html" . -}} {{- with partial "utils/resolve-section-versions.html" $root.section -}} {{- /* The current version's URL segment. Two detection paths, in order: 1. An explicit `latest = true` flag on the current version entry. This is the deliberate opt-in and works for ANY convention — a repo whose current version is a bare number (e.g. docs hub `linkVersion=2.3.x`) can only be marked this way. 2. Fallback: an entry whose `linkVersion` is literally "latest". kgw-oss and agw-oss serve the current version at /…/latest/, so the URL segment already encodes "current" and no extra field is needed. Repos matching neither (no flag, no "latest" segment) emit nothing — same fail-safe as before. */ -}} {{- $latestSeg := "" -}} {{- range . -}}{{ if eq (.latest | default false) true }}{{ $latestSeg = .linkVersion | default .version }}{{ end }}{{- end -}} {{- if not $latestSeg -}} {{- range . -}}{{ if eq (.linkVersion | default "") "latest" }}{{ $latestSeg = "latest" }}{{ end }}{{- end -}} {{- end -}} {{- /* Only proceed for a page on a KNOWN, NON-latest version. Pages with no version segment (landings) and pages already on the latest version are left alone. */ -}} {{- if and $latestSeg $root.isVersioned (ne $root.currentVersion $latestSeg) -}} {{- /* Build the current-version equivalent of THIS page as a GetPage path: take the version root's lookup path, swap the version segment for the latest one, and re-attach the path below the version. If that page exists, this old-version page is a duplicate → noindex it. A page that exists ONLY in the old version has no equivalent and stays indexable, which is the whole point of doing this per page rather than marking every old version wholesale. $lookupPath is "//" — contentDir-relative on the docs hub (so no product segment) and "/docs/
//" on an OSS site, where contentDir is the repo root and the prefix is genuinely part of the path. Trimming the version off the END rather than string-replacing it keeps a section whose name happens to equal a version string from being rewritten. */ -}} {{- $lookupPrefix := strings.TrimSuffix (printf "%s/" $root.currentVersion) $root.lookupPath -}} {{- $latestEquiv := printf "%s%s/%s" $lookupPrefix $latestSeg $root.pathAfterVersion -}} {{- $latestEquiv = strings.TrimRight "/" $latestEquiv -}} {{- if site.GetPage $latestEquiv -}} {{- end -}} {{- end -}} {{- end -}}
