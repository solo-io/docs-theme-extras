{{- /* Shortcode: reuse-append Reads a base markdown snippet from the assets tree, appends the inner content to it, and renders the combined result through the page's markdown renderer. Parameters: - 0 (positional, required): path to the base file in the assets tree. - 1 (positional, optional): version, passed down from a parent shortcode. ASSET RESOLUTION HANDLES BOTH TREE SHAPES, and it has to. An OSS site's assets tree is FLAT (`agw-docs/snippets/x.md`), while the docs hub ASSEMBLES its tree per version at `assets///…`. So the versioned path is tried first and the bare path second: 1. `//` — the hub's assembled shape. Skipped entirely when either value is empty, which is the case on every flat site. 2. `` — the bare path, correct for a flat tree and for a hub product that is not assembled. Only if BOTH miss is it an error. A single bare `resources.Get` — which is what this file did when it was first adopted from agentgateway-oss-website — resolves fine on the OSS site and misses on every assembled hub page, so the `errorf` below fired on content that was previously building. The hub had been carrying its own adapted copy of this shortcode for exactly this reason; folding the resolution in here is what lets that copy be deleted. The version comes from `utils/version-root.html`, the module's canonical version detector — NOT from a private permalink scan in this file. See the long note at the resolution step below for why that distinction is load-bearing here rather than merely tidy: the URL carries `linkVersion`, the assembled asset path is named after `version`, and on two hub products those differ. Example: {{< reuse-append "snippets/provider-base-configuration.md" >}} | Extra row | Value | {{< /reuse-append >}} WHAT IT IS FOR. A snippet that is a markdown TABLE cannot be extended by calling `reuse` and then writing more rows after it: `reuse` renders the snippet on its own, so the table is already closed as `` HTML by the time the extra rows are parsed, and they render as a stray paragraph of pipes instead of joining the table. Concatenating the two as SOURCE and rendering once keeps them a single markdown block. The same reasoning applies to any construct whose continuation depends on the preceding lines — lists, definition blocks, a fenced code block split across the boundary. IT IS NOT A VARIANT OF `reuse`. Despite the name, this shortcode does NOT apply the version- and product-aware shortcode rewrites that `reuse` does; it is a plain `resources.Get` plus concatenation. A base snippet containing a `version` shortcode, `keepVersion` blocks, or `link-hextra` calls that rely on rebase-injected params will therefore behave differently here than under `reuse`. Keep base snippets used with this shortcode free of version-dependent markup, or use `reuse` and restructure the content so appending is not needed. Errors, not warnings, on a missing positional parameter or a missing asset: both mean the call site names a file that is not there, which is a content bug that silently renders nothing if it is allowed to pass. */ -}} {{- $asset := "" -}} {{- with (.Get 0) -}} {{- $asset = . -}} {{- else -}} {{- errorf "The %q shortcode requires one positional parameter: path in /assets. Two reasons, and the second one is a correctness bug, not tidiness. 1. Every private copy of "what version is this page in" in this module has drifted from the others eventually — resolve-link.html was moved onto version-root.html for that reason, and version-noindex.html shipped two production bugs from its own copy. version-root.html also knows URL shapes a naive scan does not: it tries segment positions [2], [3], [4] and [1], which is what makes a hub product with BOTH a section segment and a language prefix (///
//…) resolve at all. 2. TWO DIFFERENT FIELDS, and this shortcode needs the less obvious one. `linkVersion` is what appears in the URL; `version` is what the docs hub's scripts/assemble-assets.py uses to build the mount target (`target_base = f"assets/{product}/{version}"`). Those are NOT always equal — gloo-mesh-enterprise and gloo-mesh-gateway both ship `version = "2.14.x"` with `linkVersion = "main"`, and `version = "2.13.x"` with `linkVersion = "latest"`. So matching the URL segment against `version` (which is what this file did when the assembled-path lookup was first added) finds NOTHING on those products: the segment is "main", no entry has version "main", the lookup is skipped, the bare path misses, and the errorf below fires.
