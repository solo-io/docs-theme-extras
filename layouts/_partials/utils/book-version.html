{{- /* book-version.html — the version string to print on THIS book's cover and in its running footer. Input is the book's root Page (`.`); output is a string, "" when there is no version to show. WHY THIS IS NOT utils/resolve-latest-version.html. That partial answers a SITE-WIDE question: "which entry in site.Params.versions carries linkVersion `latest`, else the first entry." A book is not site-wide — it only ever walks the subtree of the page that opted into the `book` output format — so the version it should print is a property of that page. The two answers agree only while the opted-in tree happens to be the flagged one, and diverge silently otherwise, because nothing in the book document or in print-book.css looks at the page at all. solo-io/docs hit exactly that on istio, which flags NO entry `latest`, so the site-wide answer fell through to the first configured entry: the 1.30.x book printed "Version 1.31.x" on its cover and in the footer of every page. The content was the right tree throughout — only the label was wrong, which is the worst shape for this kind of bug, since a reader has no way to tell. RESOLUTION ORDER: 1. `releaseVersion` on the tree's own site.Params.versions entry, when set. See WHY THIS FIELD EXISTS below. 2. Otherwise `.version` on that entry — the canonical version string, which is what most products already put there (gloo-mesh-enterprise's `latest` tree carries `version = "2.13.x"`, and its book cover reads "Version 2.13.x" with nothing extra configured). 3. `versionEntry` is "" when the version segment matched only by SHAPE — a tree with no configured entry, which version-root.html deliberately still treats as versioned. Print the matched segment itself rather than nothing. 4. An unversioned site (ambientmesh.io) is not versioned at all, so none of the above produces anything; fall back to the site-wide answer, which on such a site is "" too. The fallback is kept rather than returning "" directly so a site that grows a params.versions list without a version tree in its URLs still gets a label. WHY `releaseVersion` EXISTS, rather than just fixing `.version`. Three products in solo-io/docs — agentregistry, kagent and agentgateway — set `version = "latest"` literally on their current tree and keep the real release number only in `dropdown` ("2026.8.0 (latest)"). Their covers therefore read "Version latest", which tells a reader holding the PDF nothing about what they are holding, and is worse on paper than on the web: a downloaded file outlives the release it documents. Correcting `.version` to the real number is the obvious fix and it is not safe. That field is NOT display-only. `assemble-assets.py` names asset directories `assets//`, and `_shortcodes/reuse.html` finds them by matching each URL segment against `.version` — so for agentgateway, whose URL segment IS `latest`, renaming the field breaks the match, `$resolvedVersion` comes back empty, and every reused snippet silently falls back to the unversioned asset path. `reuse.html` and `rebase.html` also substitute `.version` into content for the OSS→enterprise version remap. None of that fails loudly. So the print label gets its own field. Nothing else reads it, it is opt-in per entry, and a product whose `.version` is already correct needs nothing. It is deliberately NOT parsed out of `dropdown`: that string is a UI label, carries a "(latest)" suffix, and is sometimes a single space to hide an entry from the switcher. A caller should treat "" as "omit the version line", not as an error — ambientmesh.io renders a book with no version at all and always has. ASSIGN the version-root result, then read it. Do NOT write `{{ with partial "utils/version-root.html" . }}`: `with` rebinds the dot to the returned dict, and Hugo's return-partial wrapper then calls `._pushPartialDecorator` on it, so the build dies pointing at version-root.html:1:10 — a location with nothing to do with the mistake. See the same warning inside version-root.html itself. */ -}} {{- $v := "" -}} {{- $vr := partial "utils/version-root.html" . -}} {{- if $vr.isVersioned -}} {{- with $vr.versionEntry -}} {{- $v = .releaseVersion | default .version | default .linkVersion -}} {{- end -}} {{- if not $v -}} {{- $v = $vr.currentVersion -}} {{- end -}} {{- end -}} {{- if not $v -}} {{- $v = partial "utils/resolve-latest-version.html" . -}} {{- end -}} {{- return $v -}}
