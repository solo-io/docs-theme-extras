{{/* page-context — return the rendering context for the current page. Returns a dict with: section the section / product name (e.g. "kubernetes", "test") version the version slug for the page (e.g. "v2", "main") condition the buildCondition string (drives `conditional-text`) prefix the URL prefix to prepend to relative paths in cards/links (e.g. "/docs/kubernetes/v2", "/test/v2") sectionSegment the page's own section under [params.sections], or "" — the SECOND gating axis, alongside `condition`. See below. WHY `sectionSegment` IS SEPARATE FROM `section`. `section` means two different things depending on the mode: the PRODUCT folder in "siteParams", the section in "url". That wart predates this partial's current callers and is not worth unpicking, so the gating axis gets its own key with one meaning in both modes. It is returned rather than recomputed by callers because this partial ALREADY resolves it in "siteParams" mode — it needs the section to know where the version segment sits. `conditional-text` used to call utils/section-segment a second time for the same answer, on every gate on every page. IN "url" MODE IT IS POPULATED ONLY WHERE `condition` IS. Both come from the same branch below, which requires a section AND a version in the path. So on a section LANDING page (/docs/
/, no version) both are "" even though utils/section-segment would match the segment. That is deliberate, not a gap: it is the whole of the OSS half of the landing-page divergence documented in layouts/_shortcodes/conditional-text.html, and keeping it here means the two modes disagree in exactly one place that can be read at a glance. Resolving it properly would mean calling utils/section-segment on every "url"-mode page — every card and every link, not just gates — to change the answer only for pages whose gates are dropped anyway. Dispatches on Site.Params.pageContextMode: "siteParams" — derives from explicit Site.Params (folder, currentProduct, buildCondition, versions). Used by multi-product hubs: the host owns the "//" path prefix so it doesn't appear in Page.RelPermalink. "url" — parses Page.RelPermalink as /docs/
//... (fallback /docs//...). Used by single-site repos where the URL itself encodes section and version. Auto-detection: if pageContextMode isn't set, the partial picks "siteParams" when Site.Params.folder is set (signals multi-product hub config) and "url" otherwise. Set the mode explicitly to override. */}} {{- $mode := .Site.Params.pageContextMode -}} {{- if not $mode -}} {{- if .Site.Params.folder -}} {{- $mode = "siteParams" -}} {{- else -}} {{- $mode = "url" -}} {{- end -}} {{- end -}} {{- $section := "" -}} {{- $version := "" -}} {{- $condition := "" -}} {{- $prefix := "" -}} {{- $sectionSegment := "" -}} {{- if eq $mode "siteParams" -}} {{- $folder := .Site.Params.folder | default "" -}} {{- /* A product with more than one parallel documentation section (site.Params.sections, see utils/section-segment.html) nests its version trees one level deeper, under a section segment: //
//…. .Page.FirstSection only returns the first path level under the product, which would resolve to the section instead of the version in that shape, so derive the version from the full URL instead when a section is present. */ -}} {{- $sectionSegInfo := partial "utils/section-segment.html" .Page -}} {{- $sectionSeg := $sectionSegInfo.segment -}} {{- $sectionSegment = $sectionSeg -}} {{- if $sectionSeg -}} {{- $relParts := split (strings.Trim .Page.RelPermalink "/") "/" -}} {{- $versionIdx := add $sectionSegInfo.index 1 -}} {{- if gt (len $relParts) $versionIdx -}} {{- $version = index $relParts $versionIdx -}} {{- end -}} {{- else -}} {{- $sectionUrl := .Page.FirstSection.RelPermalink -}} {{- $version = trim (replace $sectionUrl (printf "/%s" $folder) "") "/" -}} {{- end -}} {{- $section = $folder -}} {{- $condition = .Site.Params.buildCondition | default "" -}} {{- /* The language segment sits between the product and the section (///
//), and $prefix is REBUILT from params rather than sliced off the page's own URL, so it silently dropped it. Every {{< card >}} on a translated page then linked to the English copy — 67 hrefs on one agentgateway ja build. LanguagePrefix is "" for the default language, so English output is byte-identical. */ -}} {{- $lang := .Site.LanguagePrefix | default "" -}} {{- if and $folder $version -}} {{- if $sectionSeg -}} {{- $prefix = printf "/%s%s/%s/%s" $folder $lang $sectionSeg $version -}} {{- else -}} {{- $prefix = printf "/%s%s/%s" $folder $lang $version -}} {{- end -}} {{- else if $folder -}} {{- $prefix = printf "/%s%s" $folder $lang -}} {{- end -}} {{- else -}} {{/* url mode */}} {{- /* A SITE WITH NO SECTIONS FALLS BACK TO Site.Params.buildCondition. Without this, `conditional-text` is not merely limited on such a site — it is INERT. The condition below is assigned only in the branch that requires both a section and a version in the path, and with no sections registered `$known` is empty so that branch never runs. The condition stays "", the outer guard in the shortcode drops every gate, and BOTH directions vanish: `exclude-if="anything"`, which should be a no-op that emits its body, silently emits nothing. Verified against agentregistry.dev before this landed — both a probe `include-if` and a probe `exclude-if` rendered empty. Nothing to gate on is the honest answer for a site with one doc set, but silently deleting the body is not, and the trap is asymmetric: the same conref rendered by the docs hub DOES resolve a condition (`agentregistry`, or `gm` for ambientmesh content mounted into istio), so a gate can look correct downstream and be blank upstream. Set site-wide rather than inside the `/docs/` branch, because a product-level buildCondition is a property of the BUILD, not of a URL prefix. ambientmesh.io keeps marketing pages beside its docs tree and the hub applies its condition to every page; scoping this to `/docs/` would reintroduce the same upstream/downstream disagreement one level down. Strictly additive. It applies only where NO `[params.sections]` are registered, so the three section-registering OSS sites are untouched, and no url-mode consumer sets `buildCondition` today — every existing build is byte-identical until one opts in. A site that opts in should use the SAME token the hub uses for it, so one gate means one thing in both builds. */ -}} {{- if not .Site.Params.sections -}} {{- $condition = .Site.Params.buildCondition | default "" -}} {{- end -}} {{- $rel := trim .Page.RelPermalink "/" -}} {{- $parts := split $rel "/" -}} {{- if and (ge (len $parts) 2) (eq (index $parts 0) "docs") -}} {{- /* Known sections come from the keys of site.Params.sections (see utils/section-segment.html) instead of a hardcoded list, so each OSS-shaped site declares its own set by registering a table there — even an empty one — for each section it has (agentgateway: kubernetes/standalone; kgateway: envoy/agentgateway) rather than sharing one list across every consumer. */ -}} {{- $known := slice -}} {{- range $k, $_ := .Site.Params.sections -}} {{- $known = $known | append $k -}} {{- end -}} {{- if and (ge (len $parts) 3) (in $known (index $parts 1)) -}} {{- $section = index $parts 1 -}} {{- $version = index $parts 2 -}} {{- $condition = $section -}} {{- /* The two gating axes are ONE value in this mode — the condition IS the section. Setting both keys from it keeps `conditional-text` mode-agnostic, and the duplicate token it produces is harmless: utils/gate-decide.html ORs across the slice. */ -}} {{- $sectionSegment = $section -}} {{- $prefix = printf "/docs/%s/%s" $section $version -}} {{- else -}} {{- $version = index $parts 1 -}} {{- $prefix = printf "/docs/%s" $version -}} {{- end -}} {{- end -}} {{- end -}} {{- return dict "section" $section "version" $version "condition" $condition "prefix" $prefix "sectionSegment" $sectionSegment -}}
