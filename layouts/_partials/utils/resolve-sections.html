Input: a Page (passed as `.`) Output: a slice of dicts, sorted by section key: key string — the registry key ("kubernetes") label string — what to show href string — where the chip/menu item points isCurrent bool — the page being rendered is in this section isExternal bool — href came from `externalURL`, so rel=noopener A product registers a section by adding a key under site.Params.sections; see utils/section-segment.html. A product with none gets an EMPTY slice, so every caller can render unconditionally and single-section products are untouched. LABEL, in order: the section's own `title` in the registry, then the section landing page's title, then the humanized key. The landing page is where the title naturally lives ("Kubernetes", "Standalone"), so most products need no registry `title` at all. HREF resolves through site.GetPage rather than string arithmetic, because the section root is at a different depth in each shape: /docs/
//… OSS /
//… docs hub under `hugo server` //
//… docs hub in production GetPage paths are contentDir-relative, which already absorbs the product and language prefixes, so looking up the landing page and reading its .RelPermalink gets the published prefix right in all three without this partial needing to know which one it is. The previous inline implementation in sidebar.html hardcoded `/docs/%s/%s/` and was gated on `$isOSSShape`, so the hub simply never showed a section selector. VERSION REMAP. Section version sets do not always align: agentgateway's kubernetes section ships 2.3.x and 2026.7.1 while standalone ships only latest. Pointing another section's link at the CURRENT version can therefore land on a page that does not exist. So for a section that is not the current one, prefer an exact linkVersion match, then a `latest` entry, then that section's first configured version. That remap used to read `$cfg.versions` — i.e. site.Params.sections..versions, which v0.2.2 REMOVED. `$cfg.versions` has been nil ever since, so the whole remap silently no-opped and every section link reused the current version verbatim. It survived the migration sweep because the lookup was split across two statements (`$cfg := index site.Params.sections .` then `$cfg.versions`), which the repo-wide single-expression guard in tests/link-hextra-shapes.spec.ts could not see. That guard now covers the split form too. Versions come from utils/resolve-section-versions.html here, the one place that knows the tagged-list rule. `externalURL` on a section overrides the href entirely, for a section that exists only to scope version dropdowns and has no landing page of its own (kgateway's `agentgateway` section). The "you registered a section with nowhere to point" warning is therefore raised only on the DEFAULT content language, and only when a selector actually renders.
