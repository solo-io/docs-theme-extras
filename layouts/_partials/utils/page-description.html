{{- /* Plain-text page description for , OpenGraph, Twitter cards, and JSON-LD. Overrides Hextra's `_partials/utils/page-description.html`, which pipes the value through `plainify | htmlUnescape` only. `plainify` strips HTML tags but NOT markdown syntax, so a front-matter description like `... the **2.3 release**.` leaked its literal `**` into every meta tag (and into Slack/X link unfurls, which read those tags). Adding `markdownify` first renders the markdown to HTML (`**x**` -> `x`, `[a](b)` -> `a`), then `plainify` strips the tags, leaving clean plain text. Descriptions are plain-text metadata, so rendering-then-stripping is always what we want. Logic otherwise mirrors the upstream partial: explicit `.Description` wins; home falls back to the site description; other pages fall back to the rendered page summary (already HTML, so it skips markdownify). */ -}} {{- $desc := "" -}} {{- with .Description -}} {{- $desc = . | markdownify | plainify | htmlUnescape -}} {{- else -}} {{- if .IsHome -}} {{- with .Site.Params.description -}} {{- $desc = . | markdownify | plainify | htmlUnescape -}} {{- end -}} {{- else -}} {{- $desc = .Summary | plainify | htmlUnescape -}} {{- end -}} {{- end -}} {{- /* Collapse all whitespace runs to single spaces. A description is a single-line attribute value, but the summary path can reach here carrying real newlines: `reuse.html` flattens its expansion to one logical line by encoding newlines as ` `, and `htmlUnescape` above turns those straight back into literal newlines. The result was multi-line `` / `og:description` / JSON-LD values. Front-matter descriptions can carry stray newlines too (a wrapped YAML string), so normalize on every path rather than just the summary one. Measured: this accounts for the metadata diff on 693 of 1160 kgateway-oss pages when that repo first picks up the flatten. */ -}} {{- $desc = $desc | replaceRE `\s+` " " -}} {{- trim $desc " " -}}
