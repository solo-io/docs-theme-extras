{{- /* section-dropdown-label.html — the string on the section selector's BUTTON. DEFAULT: the product name (site.Params.product, falling back to site.Title). That is deliberate and load-bearing — it is what distinguishes this control from agentgateway-oss-website's generic "Docs" dropdown, and kagent-oss depends on it: it deleted its own "Docs" menu entry precisely BECAUSE this button already renders params.product (also "Docs" there), and keeping both put two buttons reading "Docs" side by side in the navbar. CURRENT SECTION: `[params.sectionDropdown] showCurrentSection = true`. The button names the section being read instead of naming anything fixed, so it reports WHERE YOU ARE the way the version button beside it reports which version you are on, and its menu is the list you move with. On docs-hub agentgateway that reads "Kubernetes" under /kubernetes/ and "Standalone" under /standalone/. FIXED TITLE: `[params.sectionDropdown] title = "…"`. A short fixed word. The two compose rather than competing, because there are pages with no current section and they are not edge cases. A product LANDING page renders the selector with every entry inactive — you are above the sections, choosing one (/agentgateway/ and kagent's /docs/ are both this). With nothing selected to report, resolution falls through: current section (if showCurrentSection and one is active) -> title (if set) -> params.product -> site.Title So `title` is not the always-label; it is the label for the pages that have no section to name, which is the only place it is still needed. Opt-in on purpose, both of them. Making the selector stop showing the product name by default would change every consumer's navbar at once and break kagent's setup above, for a preference one product has expressed. Returns the label STRING. It briefly also reported whether the label differed from the product name, so navbar.html could decide whether the version button still needed its product-name prefix — that turned out to be unwanted (the version dropdown suppresses the prefix whenever a selector renders, full stop), and the field went with it rather than staying as an unread extra. INPUT: the resolved section slice from utils/resolve-sections.html, as `.` — the same value components/section-dropdown.html renders. It needs the slice rather than the page because `isCurrent` is computed there, and re-deriving it here would mean two implementations of "which section is this page in" that can disagree. Before showCurrentSection existed this partial ignored its input entirely, which hid the fact that its two callers passed DIFFERENT things (the page from navbar.html, the slice from section-dropdown.html); harmless while unread, wrong the moment the label depends on it. */ -}} {{- $sections := . -}} {{- $label := site.Params.product | default site.Title -}} {{- /* `with` on the TABLE before any key. A bare site.Params.sectionDropdown .title is a field access on nil for every consumer that does not declare the table — which is nearly all of them — and that aborts the build rather than falling back. */ -}} {{- with site.Params.sectionDropdown -}} {{- /* Read before the range below, which rebinds the dot to a section. */ -}} {{- $showCurrent := .showCurrentSection -}} {{- with .title -}} {{- $label = . -}} {{- end -}} {{- if $showCurrent -}} {{- range $sections -}} {{- if .isCurrent -}} {{- $label = .label -}} {{- end -}} {{- end -}} {{- end -}} {{- end -}} {{- return $label -}}
