CI writes it into the page's front matter just before the production build, with solo-io/docs-tests/scripts/doc_test_inject_status.py, from the latest doc-test results. The script can also write `failed` or `partial` (a scenario whose test annotations did not attach). Neither shows a badge: a page earns it only when every scenario on it ran and passed. CALLED BY docs/single.html, inside the heading column, just before the `docs/under-heading.html` slot, so every consumer gets it with no layout file. single.html skips this call when the slot's output already holds a `test-status-badge`, so a consumer that still renders a badge from an `under-heading.html` override (this partial or its own copy) shows one badge, not two. Delete that override anyway: it is dead weight once you bump. ACCESSIBILITY. The explanation is real text inside the badge, hidden only visually (`.test-status-sr`), so a screen reader reads "Verified" and the explanation in browse mode and on focus. The tooltip is the same text drawn for sighted readers, so it is `aria-hidden` to avoid reading it twice. The badge takes focus so keyboard users can open the tooltip; the tooltip can be hovered without closing, and Esc closes it (assets/js/docs-init.js), as WCAG 1.4.13 asks of content shown on hover or focus. WHAT RAN. The same inject script also writes `test_types`, the kinds of test that ran on the page (kubernetes, config, schema, helm, functional, live, credentialed), taken from the results. `kubernetes`, `config`, and `helm` are the parts of the schema check, listed only for what the page itself has, so a standalone page never mentions Kubernetes. `schema` is their generic fallback, for results that predate the split. When it lists a kind this partial has wording for, the tooltip shows an intro line and one row per kind (a label and a one-line description) in place of the generic sentence. A kind with no wording is skipped, so a new kind never shows its raw name. A page with no known kind (older results, or a site whose inject script predates the field) keeps the generic sentence. Strings come from i18n with an English default: `testStatusVerified`, `testStatusVerifiedTooltip`, `testStatusTypesIntro`, and per kind `testType` and `testTypeDescription`.
